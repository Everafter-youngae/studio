# Everafter 문의 폼 — Google Apps Script 연동

이 사이트(`studio` 저장소)는 빌드도, 백엔드도 없는 정적 사이트입니다. `ask.html`의 문의 폼을 사이트 외부로 보내면서도
직접 발송·저장·확인이 되도록, Google Apps Script를 문의 접수용 웹훅으로 씁니다.

이 폴더의 `inquiry-handler.gs`는 **실행되지 않는 원본 보관용 사본**입니다. 실제로 동작하려면 아래 순서대로
Google 쪽에 별도로 배포해야 합니다 (자매 저장소 `wedding-mc`가 이미 같은 방식의 Apps Script 백엔드를 쓰고 있습니다).

## 배포 절차 (최초 1회)

1. 문의를 모을 새 Google Sheet를 만듭니다 (예: "Everafter 문의").
2. 시트 메뉴에서 **확장 프로그램 → Apps Script**를 엽니다.
3. 기본 `Code.gs` 내용을 지우고, 이 폴더의 `inquiry-handler.gs` 내용을 그대로 붙여넣습니다.
4. 상단의 **배포 → 새 배포**를 클릭합니다.
   - 유형: **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자** (로그인 없이도 사이트 방문자가 제출할 수 있어야 합니다)
5. 배포 후 발급되는 **웹 앱 URL** (`https://script.google.com/macros/s/…/exec`)을 복사합니다.
6. 이 저장소의 `script.js`에서 `INQUIRY_ENDPOINT` 상수 값을 그 URL로 바꿔 넣고 커밋합니다.
7. 최초 배포 시 Google 권한 승인 팝업이 뜨면 본인 계정으로 승인합니다 (스프레드시트 쓰기, 메일 발송 권한).

## 이후 문의 확인·처리

- 새 문의가 오면 시트에 자동으로 한 행이 추가되고, 동시에 `juhyeonjeon.lina@gmail.com`으로 이메일 알림이 갑니다.
- 시트의 **상태** 열 값을 직접 바꿔가며 처리 현황을 관리할 수 있습니다 (예: 신규 → 연락함 → 확정).
- 스크립트 내용을 고치면, Apps Script 편집기에서 **배포 → 배포 관리 → 수정(연필 아이콘) → 새 버전**으로 다시
  배포해야 반영됩니다. 이때 웹 앱 URL 자체는 바뀌지 않습니다.

## 알아둘 점

- Apps Script 웹 앱은 CORS 헤더를 보내지 않습니다. 그래서 `script.js`는 `fetch`를 `mode: 'no-cors'`로 호출하며,
  이 경우 브라우저에서 응답 내용(성공/실패 여부)을 읽을 수 없습니다. 요청 자체가 네트워크 오류 없이 나갔으면
  성공으로 간주해 안내 문구를 보여줍니다 — 실제 처리 성공 여부는 이메일 수신 또는 시트 확인으로 최종 확인해주세요.
- 폼에는 화면에 보이지 않는 허니팟(`website`) 입력칸이 있습니다. 스팸 봇은 보통 이 칸까지 채우기 때문에,
  값이 있으면 서버(Apps Script)에서 조용히 무시합니다.
